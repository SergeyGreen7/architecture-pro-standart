# ADR-003: Простая архитектура MVP открытия депозитов

## Контекст

В MVP банк принимает заявки на депозит через сайт и интернет-банк. Менеджер депозитного бэк-офиса по-прежнему проверяет заявку и открывает депозит в АБС вручную.

АБС перегружена и масштабируется только вертикально. Поэтому интернет-банк не должен обращаться к ней напрямую. Ставки необходимо перенести из XLS-файлов в единое хранилище, а новую СМС-логику реализовать без изменения ядра интернет-банка подрядчиком.

## Use Cases

| Код | Участники | Сценарий |
|---|---|---|
| UC1 | Новый клиент, сайт | Клиент видит актуальные ставки и подаёт заявку, указав Ф. И. О. и телефон. |
| UC2 | Менеджер кол-центра | Получает заявку с сайта, звонит клиенту и фиксирует результат разговора. |
| UC3 | Новый клиент, сотрудник отделения, АБС | Клиент проходит идентификацию, после чего сотрудник оформляет депозит в АБС. |
| UC4 | Клиент банка, интернет-банк | Клиент видит общие и персональные ставки, выбирает счёт и сумму и подтверждает заявку СМС-кодом. |
| UC5 | Менеджер депозитного бэк-офиса, АБС | Менеджер проверяет подтверждённую заявку, согласует условия и открывает депозит. |
| UC6 | Депозитный и кредитный бэк-офисы | Сотрудники с разными ролями управляют единым справочником ставок. |
| UC7 | Клиент, СМС-шлюз | Клиент получает уведомление после подтверждения ставки и открытия депозита. |

## Архитектурно значимые требования

| Код | Требование |
|---|---|
| NFR1 | Сервисы MVP работают 24/7 с доступностью не ниже 99,9%. |
| NFR2 | Заявка не теряется, если АБС временно недоступна. |
| NFR3 | Новые компоненты горизонтально масштабируются и могут работать в основном и резервном ЦОД. |
| NFR4 | Трафик с персональными данными и СМС-кодами шифруется. |
| NFR5 | Интернет-банк не вызывает API или БД АБС в новом процессе. |
| NFR6 | Решение использует знакомые банку технологии и документированные API. |

### Компоненты

1. **Deposit Service** — одно новое приложение на Java/Spring Boot. Оно:
   - принимает заявки с сайта и интернет-банка;
   - хранит и выдаёт ставки;
   - генерирует и проверяет СМС-коды;
   - передаёт заявки в кол-центр;
   - в фоне синхронизирует подтверждённые заявки и статусы с АБС.
2. **Deposit DB** — одна база MS SQL для заявок, ставок, статусов и журнала обмена.
3. **Интернет-банк** — существующее ASP.NET MVC 4.5 приложение. Добавляется только депозитный интерфейс и REST-вызовы Deposit Service.
4. **АБС** — существующие Delphi-клиент, PL/SQL-ядро и Oracle. Бэк-офис продолжает работать в привычном интерфейсе.
5. **Система кол-центра и СМС-шлюз** переиспользуются без создания новых промежуточных сервисов.

### Интеграции

| Откуда → куда | Назначение | Способ |
|---|---|---|
| Сайт / интернет-банк → Deposit Service | Ставки, создание и просмотр заявки | HTTPS/REST |
| Deposit Service → система кол-центра | Заявка с сайта и результат звонка | HTTPS/REST |
| Deposit Service → СМС-шлюз | СМС-код и уведомления | Защищённый API шлюза |
| Deposit Service → АБС | Передача подтверждённых заявок в фоне | Контролируемые PL/SQL-процедуры с ограничением нагрузки |
| АБС → Deposit Service | Статус обработки и открытия | Фоновый опрос или ответ через тот же интеграционный интерфейс |

Если АБС недоступна, заявка остаётся в Deposit DB и повторно передаётся позже. Для MVP отдельный брокер сообщений не нужен.

### Участвующие команды

| Команда | Работа |
|---|---|
| Цифровая трансформация | Deposit Service, Deposit DB и интерфейс управления ставками. |
| Команда сайта | Каталог депозитов и форма заявки. |
| Команда интернет-банка | Депозитный UI и REST-интеграция без изменения ядра подрядчиком. |
| Команда АБС | PL/SQL-интерфейс и экран ручной обработки заявки. |
| Команда кол-центра, инфраструктура и ИБ | Интеграция обращений, СМС, два ЦОД, TLS и мониторинг. |

## Альтернативы

### Прямая интеграция интернет-банка с АБС

Самый короткий путь, но он создаёт дополнительную онлайн-нагрузку на перегруженную АБС. Альтернатива отклонена.

### Реализовать всю логику в интернет-банке

Не подходит сайту, увеличивает зависимость от подрядчика и связывает продуктовую логику с монолитом. Альтернатива отклонена.

### Сразу использовать Kafka и несколько микросервисов

Это улучшит масштабирование в будущем, но усложнит MVP, а текущий интернет-банк несовместим с Kafka. Решение можно пересмотреть после проверки нагрузки.

## Последствия и риски

| Риск | Мера |
|---|---|
| Deposit Service объединяет несколько функций. | Сохранить модульную структуру приложения и понятные внутренние границы. |
| Статус в Deposit DB может временно отличаться от АБС. | Использовать сквозной ID, повторную передачу и регулярную сверку. |
| Фоновая синхронизация может перегрузить АБС. | Ограничить скорость и контролировать очередь и метрики АБС. |
| Ручная обработка ограничивает скорость MVP. | Измерять время обработки; автоматизацию вынести в следующий этап. |
