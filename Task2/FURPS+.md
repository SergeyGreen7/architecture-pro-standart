# Задание 2. Требования FURPS+

Таблица фиксирует основные требования к цифровизации депозитов и кредитов. В неё включены только требования, влияющие на MVP и архитектурные решения.

## F — Functionality

| Код | Требование | Комментарий |
|---|---|---|
| F1 | Сайт и интернет-банк показывают актуальные условия депозитов и кредитов. | В интернет-банке также доступны персональные ставки и предодобренные кредитные предложения. |
| F2 | Новый клиент подаёт на сайте заявку на депозит, указав Ф. И. О. и телефон. | Заявка поступает в кол-центр; после консультации клиент проходит идентификацию в отделении. |
| F3 | Новый клиент подаёт на сайте заявку на кредит. | При указании паспортных данных система выдаёт предварительное решение на основе скоринга и данных БКИ. |
| F4 | Клиент интернет-банка подаёт заявку на депозит, выбирает счёт и сумму и подтверждает операцию СМС-кодом. | В MVP условия подтверждает сотрудник бэк-офиса в АБС. |
| F5 | Клиент интернет-банка подаёт заявку на кредит и выбирает счёт зачисления. | Поддерживаются предодобренные предложения и подтверждение СМС-кодом. |
| F6 | Клиент получает СМС об изменении статуса заявки, подтверждении ставки и открытии продукта. | Используется существующий СМС-шлюз банка. |
| F7 | Онлайн-заявка имеет сквозной идентификатор и доступна для продолжения работы в отделении и бэк-офисе. | Повторно создавать уже поданную заявку не требуется. |
| F8 | Актуальные депозитные ставки доступны депозитному и кредитному бэк-офисам и кол-центрам. | Партнёрский кол-центр получает ставки файловым обменом. |

## U — Usability

| Код | Требование | Комментарий |
|---|---|---|
| U1 | Интерфейсы соответствуют дизайн-системе банка и понятны без обучения. | Формы должны быть удобны в том числе для возрастных клиентов. |
| U2 | Форма содержит только необходимые поля и показывает понятные статусы и ошибки. | Клиент должен понимать результат каждого шага и дальнейшие действия. |

## R — Reliability

| Код | Требование | Комментарий |
|---|---|---|
| R1 | Цифровые сервисы работают 24/7 с доступностью не ниже 99,9%. | Требование относится к новым клиентским и интеграционным компонентам. |
| R2 | Сбой отдельного сервера или основного ЦОД не приводит к потере заявки. | Требуются резервирование и переключение на резервный ЦОД. |
| R3 | Повторная отправка запроса не создаёт дубликат заявки или финансовой операции. | Интеграции должны поддерживать повторную доставку и идемпотентность. |

## P — Performance

| Код | Требование | Комментарий |
|---|---|---|
| P1 | Пользовательские операции и загрузка справочных данных выполняются за миллисекунды, а не секунды. | Точные пороги и перцентили необходимо зафиксировать перед нагрузочным тестированием. |
| P2 | Новые сервисы поддерживают горизонтальное масштабирование и балансировку между серверами и ЦОД. | Рост цифрового канала не должен требовать масштабирования АБС. |
| P3 | Новые процессы не создают дополнительную пиковую нагрузку на АБС и систему скоринга. | Массовый предварительный скоринг не допускается. |
| P4 | Предодобренная кредитная заявка обрабатывается в течение рабочего дня. | Текущий суточный обмен АБС с кредитным конвейером не обеспечивает эту цель. |

## S — Supportability

| Код | Требование | Комментарий |
|---|---|---|
| S1 | Используются совместимые с ландшафтом банка технологии, по которым есть внутренняя экспертиза. | Приоритет: .NET, Java, Python, MS SQL, Oracle и PostgreSQL. |
| S2 | API, интеграционные контракты и эксплуатационные процедуры документируются и версионируются. | Документация должна позволять добавлять новые продукты и каналы. |
| S3 | Новые компоненты имеют централизованные логи, метрики и оповещения о сбоях. | Необходимо контролировать доступность, задержки и ошибки интеграций. |

## + — Ограничения

| Код | Ограничение | Влияние |
|---|---|---|
| C1 | Новый клиент должен пройти очную идентификацию в отделении. | Сайт принимает заявку, но не завершает открытие продукта полностью онлайн. |
| C2 | Чувствительные данные сайта и интернет-банка передаются только по защищённому каналу. | Для внешних и внутренних API обязательно шифрование трафика. |
| C3 | АБС перегружена и масштабируется только вертикально. | В новых процессах запрещена прямая онлайн-интеграция интернет-банка с API АБС. |
| C4 | Текущая платформа интернет-банка несовместима с Kafka. | Kafka допустима в перспективе через отдельный совместимый интеграционный слой. |
| C5 | Обмен АБС с кредитным конвейером выполняется раз в сутки и не может быть просто ускорен. | Для решения по кредиту в течение дня нужен поток, не зависящий от существующего batch-обмена. |
| C6 | В MVP депозитную заявку обрабатывает сотрудник бэк-офиса. | Автоматическое открытие без участия бэк-офиса относится к следующему этапу. |
| C7 | Депозитный и кредитный бэк-офисы не получают прямой доступ к данным друг друга. | Обмен должен предоставлять только необходимые данные с контролем прав доступа. |
