# Задание 2. FURPS+ для MVP депозитов

Таблица содержит основные требования к подаче заявки на депозит через сайт и интернет-банк. Требования следующих этапов и кредитного направления не включены.

## F — Functionality

| Код | Требование | Комментарий |
|---|---|---|
| F1 | Сайт показывает список доступных депозитов с актуальными ставками. | Информация доступна новому клиенту без авторизации. |
| F2 | Новый клиент подаёт на сайте заявку, указав Ф. И. О. и номер телефона. | Заявка передаётся менеджеру кол-центра для обратного звонка и предложения условий. |
| F3 | Интернет-банк показывает актуальные и персонализированные ставки клиента. | Персональные условия доступны только авторизованному клиенту. |
| F4 | Клиент интернет-банка подаёт заявку, указав депозит, счёт списания и сумму. | Операция подтверждается СМС-кодом. |
| F5 | Ставки ведутся централизованно и доступны депозитному и кредитному бэк-офисам. | Необходимо заменить текущую работу только через XLS-файлы. |
| F6 | Менеджер депозитного бэк-офиса обрабатывает заявку и подтверждает условия в АБС. | Это целевой процесс только для MVP. |
| F7 | Клиент получает СМС после подтверждения ставки и после открытия депозита. | Бизнес-логику желательно реализовать силами команды банка. |

## U — Usability

| Код | Требование | Комментарий |
|---|---|---|
| U1 | Формы и сценарии должны быть простыми и понятными клиенту. | Следует минимизировать число полей и шагов. |
| U2 | Сайт и интернет-банк соответствуют принятой дизайн-системе банка. | Используются привычные цвета, элементы и брендирование. |

## R — Reliability

| Код | Требование | Комментарий |
|---|---|---|
| R1 | Сервисы MVP работают 24/7 с доступностью не ниже 99,9%. | Доступность должна контролироваться для каждого критичного компонента. |
| R2 | Сбой основного ЦОД не приводит к длительной недоступности интернет-банка. | Требуется переключение на резервный ЦОД. |
| R3 | Заявки не теряются при временной недоступности АБС или интеграции. | Передача должна поддерживать безопасный повтор после восстановления. |

## P — Performance

| Код | Требование | Комментарий |
|---|---|---|
| P1 | Пользовательские операции выполняются с откликом в миллисекундах. | Конкретные пороги и перцентили следует согласовать до нагрузочного тестирования. |
| P2 | Новые компоненты горизонтально масштабируются и поддерживают балансировку нагрузки. | Запросы распределяются между серверами, приложениями и ЦОД. |
| P3 | Новый процесс не увеличивает критическую нагрузку на базу АБС. | Часто читаемые ставки и справочные данные не следует каждый раз получать из АБС. |

## S — Supportability

| Код | Требование | Комментарий |
|---|---|---|
| S1 | Приоритет получают технологии, совместимые с платформами банка и знакомые внутренним командам. | В банке уже используются MS SQL, Oracle и несколько распространённых языков разработки. |
| S2 | Новые компоненты депозитного процесса проектируются модульно. | Это позволит развивать функциональность отдельно от монолита интернет-банка. |
| S3 | Архитектура, API и эксплуатационные процедуры документируются. | Документация должна поддерживать дальнейшее расширение решения. |

## + — Ограничения

| Код | Ограничение | Влияние на решение |
|---|---|---|
| C1 | Новый клиент должен пройти личную идентификацию в отделении. | Сайт принимает заявку, но не открывает депозит полностью онлайн. |
| C2 | Чувствительные данные сайта и интернет-банка передаются только по зашифрованному каналу. | Все внешние и внутренние сетевые взаимодействия требуют защиты трафика. |
| C3 | В MVP заявку обрабатывает сотрудник бэк-офиса. | Полностью автоматическое открытие депозита находится вне текущего этапа. |
| C4 | Следует избежать прямой работы интернет-банка с API АБС. | Перегруженная АБС не должна быть синхронной точкой входа нового массового канала. |
| C5 | АБС масштабируется только вертикально. | Масштабирование цифрового канала должно выполняться в новых компонентах. |
| C6 | Текущая версия интернет-банка несовместима с Kafka. | Kafka рассматривается на перспективу через совместимый интеграционный слой, но не является обязательной частью MVP. |
| C7 | Доработку СМС-функциональности ядра подрядчиком желательно исключить. | Бизнес-логику подтверждения и уведомлений реализует команда банка вне ядра платформы. |
